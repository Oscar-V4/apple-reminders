# Apple Reminders 공개 배포 방향

2026-09-05 기준의 제품 판단과 이번 변경의 범위다. 새 릴리스가 배포됐거나 새 Mac에서 검증이 끝났다는 발표 문서는 아니다. 구현 계약은 [ADR 0021](decisions/0021-core-default-experience.md)에 기록한다.

이 플러그인은 안전한 변경을 위한 기반을 이미 많이 갖췄다. 이제 우선할 일은 지원 기능을 계속 늘리는 것보다, 처음 설치한 사람이 개발 도구를 배우지 않고 일상적인 할 일을 처리할 수 있게 만드는 것이다. **기본 기능은 작고 안정적으로 제공하고, macOS 내부 구조에 의존하는 기능은 명시적으로 선택하게 한다.**

## 지금까지 만든 것의 가치

AI가 만들었다는 사실이나 테스트 개수만으로 신뢰할 수 있는지는 판단할 수 없다. 잘못된 대상을 바꾸지 않는지, 결과를 실제로 확인하는지, 배포한 프로그램의 출처를 추적할 수 있는지가 더 구체적인 판단 기준이다.

이 저장소에는 그 기준에 해당하는 설계와 테스트가 있다.

- 이름이 같은 목록이나 할 일을 구별하기 위해 정확한 ID를 사용한다. 기존 항목을 바꿀 때는 최근 조회에서 받은 Revision으로 오래된 상태를 덮어쓰지 않도록 한다.
- Receipt는 변경 없음, 확인된 성공, 확인 대기, 일부 성공 등을 구별한다. 명령이 종료됐다는 이유만으로 동기화나 iPhone 표시까지 성공했다고 말하지 않는다.
- 기본 EventKit helper는 서명·공증·출처 manifest를 갖춘 배포물이다. 일반 사용자가 처음 실행할 때 Core helper를 컴파일하는 방식은 이미 제거됐다.
- private 경로는 알려진 macOS·Reminders 빌드와 스키마 증거를 요구한다. 컴파일이 되거나 비슷한 테이블이 있다는 이유로 새로운 OS를 지원한다고 간주하지 않는다.

근거는 [Core 계약 테스트](../tests/test_mcp_v2_core.py), [변경 결과 테스트](../tests/test_adapter_mutation_receipts.py), [EventKit bridge 테스트](../tests/test_eventkit_bridge.py), [Experimental admission 테스트](../tests/test_experimental_capabilities.py), [서명 helper 결정](decisions/0019-prebuilt-signed-eventkit-core-helper.md), [릴리스 검증 절차](release-verification.md)다. 이들은 검증 가능한 안전장치의 존재를 보여준다. 이번 변경의 테스트 통과 여부나 새 사용자 환경에서의 작동까지 이 문서가 대신 증명하지는 않는다.

## 일반 사용자에게 여전히 어려운 부분

Xcode를 개발자가 사용하는 것 자체는 문제가 아니다. 사용자가 할 일을 하나 추가하려다가 Xcode나 개발 도구 설치를 요구받는 경험이 문제다. Core helper의 사전 빌드로 큰 장애물 하나는 해결했지만, Python 3.11 이상은 여전히 필요하다. 개발자의 Mac에서 잘 실행되는 것과, 개발환경이 없는 사람의 Mac에서 쉽게 설치되는 것은 별개의 조건이다.

또한 섹션, 태그, 이미지 첨부, 최근 삭제 항목 복구는 Apple의 공개 EventKit만으로 제공하는 기능과 지원 조건이 다르다. 일부는 로컬 컴파일을 요구하고, 모두 같은 수준의 호환성을 약속할 수 없다. 이를 기본 도구 목록에 함께 노출하면 에이전트가 평범한 요청을 복잡한 경로로 처리할 수 있다. 특히 기존 URL 입력은 EventKit 저장과 native URL 첨부를 결합하므로, 링크 하나 저장하는 일에도 private 경로의 실패가 끼어들 수 있었다.

여기서 하드닝을 계속 추가하면 개별 실패를 줄일 수 있지만, 검증해야 할 조합과 유지보수 범위도 늘어난다. 대중에게 필요한 핵심 사용 경험이 좋아지는지 함께 평가해야 한다.

| Google Calendar 1.2.7 설치 패키지 | manifest와 등록된 connector 연결로 구성되며 별도 스킬·로컬 컴파일 경로가 없다. 도구 설명은 범위를 정한 검색, 정확한 이벤트 ID, 변경 전 상세 확인을 안내한다. | 사용자에게는 일정 관리라는 목적을 보여주고, 입력·대상·결과의 경계는 도구 계약에 둔다. |
| 공식 Apple Messages 1.0.1000926 앱 번들 | 작은 MCP launcher가 호스트에 이미 포함된 native client를 실행한다. 별도 스킬이 없으며 사용자가 빌드할 필요가 없다. 로컬 client의 OpenAI Developer ID 서명도 확인했다. | native 기능은 준비된 실행환경으로 배포한다. 설치·권한·사용 단계를 짧게 만든다. |

Google Calendar의 공개 패키지 위치는 [OpenAI plugins 저장소](https://github.com/openai/plugins/tree/main/plugins/google-calendar)다. 이번 구조 비교는 로컬에 설치된 위 버전의 manifest와 현재 세션에 제공된 도구 정의를 기준으로 했으며, 호스팅된 connector의 내부 구현은 검토하지 않았다.

Messages는 [2026-08-20 공식 변경기록](https://learn.chatgpt.com/docs/changelog)에 공개됐고, [현재 사용 문서](https://learn.chatgpt.com/docs/plugins)는 macOS Apple Silicon의 ChatGPT 데스크톱에서 Codex와 Work로 사용하는 범위를 명시한다. 설치 후 필요한 macOS 권한을 허용하고, 기본적으로 발송할 내용과 수신자를 확인한다. 이 프로젝트에서 비교한 것은 앱에 포함된 manifest·MCP 설정·launcher와 공식 문서이며, 비공개 native 구현이나 개인 메시지를 조사한 것은 아니다.

두 사례를 그대로 복제하지는 않는다. Google Calendar는 서버와 계정 연결을 사용하는 서비스이고, Reminders는 Mac의 로컬 데이터에 접근한다. Messages의 비공개 호스트 client와 승인 UI는 서드파티 플러그인이 재사용할 수 있는 공개 기반으로 간주하지 않는다. 메시지 발송의 승인 절차를 모든 개인 할 일 변경에 똑같이 적용할 필요도 없다. 사용자의 명확한 요청은 존중하고, 실제 macOS 권한과 위험한 변경의 정확한 대상 확인은 유지한다.

## 이번에 선택한 기본 경험

기본 실행은 Core 8개 도구와 진단 1개, 총 9개만 제공한다. 할 일과 목록 조회, 추가, 변경, 완료, 삭제, 목록 생성, Reminders 접근 권한 요청이 일상 작업의 중심이다. 진단은 관련 오류가 생겼을 때 사용한다.

Native Extension과 Recovery의 6개 도구는 시작할 때 `--experimental`을 명시한 runtime에서만 제공한다. 도구 목록은 실행 중 바뀌지 않으며, 기본 실행에 숨겨진 도구 이름을 직접 보내도 거부한다. 이 선택은 도구를 사용할 수 있게 하는 설정일 뿐이다. 알려진 OS·앱 빌드, 스키마, 필요한 컴파일러, 정확한 변경 전후 검증이라는 기존 조건을 완화하지 않는다.

기본 Core의 URL은 공개 EventKit의 URL 필드로 저장하고 그 값만 확인한다. Reminders 앱에 별도 URL 카드가 생기거나 iPhone에 어떻게 보이는지까지 약속하지 않는다. `--experimental` 실행에서는 기존의 EventKit + native URL 첨부 결합 동작을 유지하므로, 그 동작이 필요한 기존 사용자는 명시적으로 선택할 수 있다.

실행기는 Apple의 `/usr/bin/python3` 개발 도구 shim을 시험 실행하지 않도록 하고, 사용할 수 없는 Python으로 넘어가는 fallback을 제거한다. Python을 찾지 못하면 필요한 버전과 설치 방법을 알려준다. **이 수정으로 Python 설치 필요성이 없어지는 것은 아니다.**

기존 서명 EventKit helper와 출처 자료는 유지한다. 이번 Python·MCP·문서 변경을 이유로 native helper를 다시 빌드하거나 버전을 올리지 않는다. 실제 배포 여부와 검증 결과는 별도 릴리스 기록으로 남겨야 한다.

## 이번 변경의 검증 기록

2026-09-05 현재 작업 Mac에서 다음을 확인했다.

- 자동 테스트 832개 통과. 기본/실험 도구 분리, 차단된 직접 호출, URL 저장, 모드 전환 시 중복 생성 방지, Python 탐색, 설치 패키지를 포함한다.
- 실제 Reminders의 별도 합성 목록에서 14단계 Core 점검 통과: 목록·항목 생성과 재요청, URL 저장·재조회, 수정, 오래된 수정 거부, 완료·재개, 삭제·부재 확인, 정확한 테스트 목록 정리.
- 플러그인·Minis·스킬·공개 문구·배포 파일 검사, Python/Objective-C 문법 검사 통과. 기존 universal helper의 Developer ID 서명과 공증·manifest를 재검증했다.
- 배포 ZIP을 별도 디렉터리에서 두 번 만들어 바이트 단위 일치를 확인했다. 서명 helper 파일은 변경하지 않았다.

이 기록은 기존 권한이 있는 현재 Mac의 결과다. 새 Mac·새 TCC 사용자·개발 도구가 없는 실제 환경의 검증이나 실험 기능 전체의 실행 검증으로 확대해서 해석하지 않는다. 공개 v0.5.2 릴리스에 이 변경이 자동으로 포함되는 것도 아니다.

## 다음 개발의 우선순위

1. **실행환경을 함께 배포한다.** 사용자가 Python을 별도로 설치하지 않아도 되는 서명된 배포물을 준비한다. 기존 안전 계약과 EventKit helper를 보존하면서, 포함된 실행환경의 업데이트·라이선스·출처 검증을 함께 설계한다. 언어를 전면 교체하는 것은 설치 문제를 해결하는 데 필요하다는 근거가 있을 때 판단한다.
2. **개발환경이 없는 외부 Mac에서 검증한다.** Finder에서 실행한 Codex, Xcode/Command Line Tools/Python이 없는 환경, 첫 권한 허용과 거부, 권한 철회 후 안내, 업데이트 후 권한 유지, 실패 시 복구 경로를 확인한다. 현재 개발 Mac의 성공으로 대체하지 않는다. 특히 새 사용자 프로필과 새 Mac에서의 TCC 권한 흐름은 아직 열려 있는 배포 조건이다.
3. **실제 사용자가 세 가지 일을 끝내는지 본다.** 오늘·지연된 할 일 확인, 지정 목록에 기한을 넣어 추가, 방금 만든 항목을 수정하고 완료하는 흐름을 검증한다. 회의 메모에서 여러 할 일을 만드는 작업은 그다음이다. 소요 시간, 불필요한 질문, 개발 도구 요구, 오류 뒤에 사용자가 할 수 있는 행동을 기록한다.

실험 기능을 추가할 때는 먼저 자주 발생하는 사용자 필요인지, 공개 인터페이스나 수동 대안으로 해결할 수 있는지, 별도 유지보수와 검증 비용을 감당할 수 있는지 판단한다. 기능 수보다 **처음 설치한 사용자가 도움 없이 일상 작업을 마칠 수 있는 비율**을 개선의 기준으로 삼는다.
