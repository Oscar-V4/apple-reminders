## English SNS post

> I shipped v0.4.0 of an independent, open-source Apple Reminders plugin for
> Codex.
>
> It separates EventKit-based core workflows from version-sensitive native
> extensions and models uncertain writes with idempotency, stale-write
> rejection, and final read-back receipts. The plugin runtime executes locally
> on the Mac; tool results return to Codex.
>
> I published a pinned install, deterministic ZIP/checksum, 615 regression
> tests, an isolated-install receipt, and a 23-step live synthetic macOS smoke
> receipt.

## Developer Forum draft

Suggested title:

> Apple Reminders for Codex v0.4.0 — independent local-MCP pre-release, looking for Mac testers

Body:

> I released v0.4.0 of an independent open-source Apple Reminders plugin for
> Codex. The project addresses a narrow problem: let Codex work with the
> Reminders data available to a person's Mac without turning the integration
> into a hosted reminder-data service.
>
> Routine operations use EventKit. Sections, tags, native attachments, and
> Recently Deleted recovery are isolated as version-sensitive capabilities.
> Writes use opaque short-lived references, idempotency, stale-write rejection,
> and exact read-back Receipts so a process exit or uncertain timeout is not
> reported as generic success.
>
> Install the pinned release:
>
> ```bash
> codex plugin marketplace add Oscar-V4/apple-reminders --ref v0.4.0
> codex plugin add apple-reminders@oscar-v4-reminders
> ```
>
> Requirements: macOS 14+, Python 3.11+, Xcode Command Line Tools, and explicit
> Reminders permission. The plugin runtime runs locally, while tool results
> return to Codex under the user's product/account boundary.
>
> Release: https://github.com/Oscar-V4/apple-reminders/releases/tag/v0.4.0
> Evidence: https://github.com/Oscar-V4/apple-reminders/blob/ac5bae536a8c9864abcc226a9742723076624c2f/docs/release-evidence/v0.4.0.md
> Privacy: https://github.com/Oscar-V4/apple-reminders/blob/v0.4.0/PRIVACY.md
>
> I am looking for testers on other Macs and supported macOS/Python setups.
> Please use a disposable list and synthetic content, then report only the
> redacted status/Receipt category through
> https://github.com/Oscar-V4/apple-reminders/issues/new/choose.
>
> The current release passed one-Mac live smoke and clean-install checks, but a
> genuinely fresh TCC allow/deny/retry journey and external-user validation are
> still pending. This is an independent community project and is not endorsed
> by OpenAI or Apple.
