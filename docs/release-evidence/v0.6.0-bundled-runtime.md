# v0.6.0 bundled-runtime verification

This record describes observed checks for the v0.6.0 candidate. The versioned
[GitHub Release](https://github.com/Oscar-V4/apple-reminders/releases/tag/v0.6.0)
is the publication record. This document does not establish fresh-user
Reminders permission behavior or execution on every supported Mac.

## Runtime provenance and native execution

The [runtime preparation run](https://github.com/Oscar-V4/apple-reminders/actions/runs/33963352805)
completed all five jobs: unsigned build, isolated Developer ID signing and
notarization, native arm64 verification, native x86_64 verification, and final
five-subject SLSA attestation.

- Source commit: `cddb26fcbc3ff512357211e67387ef71e9f1b2fd`.
- Trusted workflow commit: `be30283bbc93d6f33b04ba3b982d2ae4f5cc2ff1`.
- Runtime: CPython 3.13.15 / python-build-standalone 20260901.
- Native hosts: GitHub-hosted `macos-15` arm64 and `macos-15-intel` x86_64.
- Both hosts checked app and nested signatures, CodeDirectory identity,
  Gatekeeper and stapled notarization, then executed standard-library imports,
  worker subprocesses and Core/Experimental MCP discovery.
- The downloaded candidate's five subjects, historical source inputs and
  attestation were independently verified against the release branch. Canonical
  main/tag ancestry is checked again by the final release verifier after merge.

The exact ZIP hashes are recorded in the committed
[`runtime/SHA256SUMS`](../../plugins/apple-reminders/runtime/SHA256SUMS).
No signing credentials were downloaded to the development Mac.

## Assembled EventKit helper

The [v0.6.0 helper preparation run](https://github.com/Oscar-V4/apple-reminders/actions/runs/33964723586)
completed signing, notarization, protocol verification, assembled-plugin checks
and its three-subject attestation. The helper source commit is
`fe9bfd492874973cf8a814dd2c78ee79678d876f`; the trusted workflow commit is
`be30283bbc93d6f33b04ba3b982d2ae4f5cc2ff1`.

The assembled source audit accepted exactly 67 files. The full synthetic suite
ran 944 tests on Python 3.12 and passed, with one explicitly opt-in runtime test
skipped. The downloaded helper's three actual artifact hashes, attestation,
expanded file hashes, Developer ID signature, notarization and data-free
protocol probes were independently verified before local assembly.

On the development Mac, the assembled plugin also passed all 944 tests using
the final bundled CPython 3.13 interpreter with the optional real-runtime test
enabled. The subsequent strict source audit again accepted 67 files.

## Installed-layout checks on the development Mac

The final capsule bytes were tested in a temporary copy of the plugin with a
new HOME and paths containing spaces on macOS 26.5.2 arm64. The environment
contained only the system PATH and deliberately invalid Python configuration.

| Observed operation | Time |
|---|---:|
| First initialization with a new runtime cache, Core 9 tools | 2.073 s |
| Warm initialization, Core 9 tools | 0.472 s |
| Experimental initialization, 15 tools | 0.475 s |
| Daily-brief renderer with synthetic JSON on stdin | 0.443 s |

These are single observed runs, not cross-machine performance promises. The
process used the capsule's Python 3.13 interpreter. All 1,676 files and 161
directories matched their recorded contents and modes afterward; the app and
11 native code files retained valid signatures. No new bytecode or execution
of the injected Python configuration was observed. These checks did not access
Reminders data.

## Live Core on an existing permission profile

The final bundled interpreter and launcher completed all 14 live Core steps on
the development Mac: exact synthetic list creation and replay, reminder creation
and replay, bounded fetch, exact reads, update, stale-reference rejection,
completion, reopening, deletion, absence verification and exact list cleanup.
The Core requests covered EventKit URL metadata and used the default tool set.
The source harness removed the exact reserved empty list through its AppleScript
cleanup seam after Core deleted the synthetic reminder.

The [redacted step log](v0.6.0-live-smoke.txt) contains only status, timing and
the fact that a writable non-delegated source was resolved. It contains no
account names, source/list/reminder IDs or user reminder content. Existing
permission on this Mac was reused; this is not a fresh-user TCC test.

## Remaining external evidence

Fresh-user permission allow/deny/revocation, permission continuity on an
external upgrade subject, and end-to-end execution on macOS 14 still require
separate acceptance records. Native Intel interpreter execution does not by
itself establish Intel Reminders permission or sync behavior. Local read-back
does not prove iCloud convergence or display on every device.
