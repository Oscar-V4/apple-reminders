# v0.7.0 packaged Native image acceptance

On 2026-09-07, the maintainer exercised the assembled `7383736` candidate ZIP
through its extracted `launch_bundled_mcp.sh`, with no mode flag. The tested ZIP
SHA-256 was `d4ddbeb64cf48ace65f0e4bbfde88c8fb0d8dbdfeade6ab7d6be3ba834c94e04`.
Later documentation changes alter the release ZIP digest without changing the
signed helper bytes identified by the committed manifests.

The host was arm64 macOS 26.5.2 (25F84), Reminders 7.0 (3976), with an existing
iCloud permission grant. The child process had `PATH=/usr/bin:/bin:/usr/sbin:/sbin`,
`DEVELOPER_DIR` pointing to a nonexistent directory, and
`APPLE_REMINDERS_NATIVE_ALLOW_SOURCE_BUILD` unset. The external test driver sent
JSON-RPC; the plugin itself used its bundled Python runtime and signed helpers.
This is a deliberately unavailable toolchain on an existing developer Mac,
not a fresh macOS installation or first-use permission test.

The synthetic flow used one newly created Reminder in an existing maintainer
test list and the plugin's public PNG icon as input:

1. Attachment diagnosis reported the signed helper verified and the exact
   image capability admitted, with no developer-tool or compiler process
   attempted. The inconclusive static private-framework path warning did not
   prevent the admitted runtime path.
2. Default Core creation returned `verified`, including a synthetic HTTPS URL.
   A fresh Core read preserved that URL; native inspection returned zero
   attachments. Thus Core URL metadata did not create an implicit URL card.
3. With a fresh reference, explicit `attach_image` returned `verified`,
   `final_read:true`, `matched:true`, and one 1024 by 1024 PNG attachment.
4. The attachment read-back included a server record, `in_cloud:1`, local and
   synced versions both 1, and `mobile_visible_likely:true`. This is CloudKit
   evidence, not direct iPhone-screen confirmation.
5. A fresh Core read preserved the synthetic title, notes, and URL. Exact Core
   deletion then returned `verified` with `local_absence:true`, cleaning up the
   newly created test Reminder. No unrelated Reminder was changed.

This acceptance covers the packaged default image-write path on the admitted
host. It does not establish section/tag mutation, recovery behavior, Intel
Native operation, minimum-macOS operation, or clean-user permission behavior.
Private identifiers and full operational receipts remain outside the repository.
